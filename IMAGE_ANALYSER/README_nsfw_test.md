# NSFW detector test harness

Local benchmark that runs every NSFW image detector against a labelled test set and
reports per-detector results + accuracy. This is the **Rust inference core** you'll
ship (cross-compiled to Android later); **Python** is used only once to convert
models to ONNX.

## TL;DR

```bash
./setup.sh
```

That's it. The script is idempotent (safe to re-run) and does everything:
creates the dirs, builds a Python venv and installs deps, converts every model to
ONNX, generates the ground-truth file from your images, builds the Rust core, and
runs the harness.

## How it fits your architecture

| Piece | Role here |
|---|---|
| **Rust** (`src/`) | Loads `.onnx`, decodes/resizes images, runs inference, thresholds, returns results. This *is* the core. |
| **Python** (`scripts/`) | One-time, offline: PyTorch/TF → ONNX, and writes a `preproc.json` sidecar per model. Never ships. |
| **ONNX** (`models/`) | The shared artifact Rust loads. Byte-identical on Debian and Android. |
| **Sidecar** (`preproc.json`) | Per-model preprocessing (size, mean/std, channel order, label map). Generated by Python so Rust never hardcodes constants. |

## Ground truth format

One JSON object mapping each image to a single boolean — `true` = NSFW:

```json
{
  "test/static/testImages/allowed.jpg":      false,
  "test/static/testImages/not-allowed1.jpg": true
}
```

If the file is missing it's generated from filenames (`*not-allowed*`/`*nsfw*` →
`true`, everything else → `false`) — review those guesses.

`setup.sh` (and a bare `cargo run`) will **generate this for you** from the images in
`test/static/testImages/` if the file is missing, using the filename convention
`*not-allowed*` → `true`, everything else → `false`. It never overwrites an existing
file, so any manual edits you make stick. Re-check a label any time by editing the file.

## Prerequisites

`setup.sh` checks these and tells you what's missing:

- **Rust ≥ 1.81** (required by `ort`). If your distro's `rustc` is older:
  `curl https://sh.rustup.rs -sSf | sh` then `source $HOME/.cargo/env`.
- **python3** (for the one-time conversion venv).
- **curl or wget** (to download the ONNX Runtime native library).

### ONNX Runtime library

`ort` is configured with `load-dynamic`, so it loads `libonnxruntime.so` at runtime
rather than downloading/linking it at build time (which avoids the OpenSSL build
dependency entirely). `setup.sh` downloads the CPU build into `./onnxruntime/` and
writes `.cargo/config.toml` so every `cargo run` finds it via `ORT_DYLIB_PATH`. This
is also how you'll ship on Android — bundle `libonnxruntime.so` in the APK.

Override the version if needed: `ORT_VERSION=1.22.1 ./setup.sh` (it re-downloads when
the version changes). `ort` rc.10 requires ONNX Runtime **1.22.x**; if you ever see a
runtime panic like *"not compatible … expected GetVersionString to return '1.22.x'"*,
the library doesn't match — set `ORT_VERSION` to a 1.22 release.

## Running

This binary is a **model test**, not the app's runtime:
```bash
cargo run --release -- --test-models                 # run the NSFW detectors
cargo run --release -- --test-models --level strict  # strict | moderate | lenient
```
`./setup.sh` runs it for you (pass `LEVEL=strict ./setup.sh` to pick a level).

It loads every detector under `models/`, runs them over the ground-truth set, and
prints a per-(model, image) table — model, image, expected, score, threshold, verdict,
ok/FAIL, ms — then an accuracy + timing summary. Results go to `test/results.json`.
A run **exits non-zero** if any model fails to load, any ground-truth image fails to
open, or any inference errors: a test should fail loudly.

### Thresholds (`models/thresholds.json`)

Cutoffs live in one file, not in each `preproc.json`. Each model has three levels:
```json
{
  "default_level": "moderate",
  "models": {
    "adamcodd-vit-nsfw": { "strict": 0.10, "moderate": 0.30, "lenient": 0.50 }
  }
}
```
Lower threshold = stricter = more images flagged NSFW. Pick a level with `--level`
(or set `default_level`). Edits take effect on the next run — no re-convert needed.

Useful env toggles for `setup.sh`:
```bash
SKIP_CONVERT=1 ./setup.sh                                   # don't (re)convert models
FORCE_CONVERT=1 ./setup.sh                                  # re-convert even if present
CONVERT_ONLY="adamcodd-vit-nsfw" ./setup.sh                 # subset only
LEVEL=strict ./setup.sh                                     # run at a given level
RUN=0 ./setup.sh                                            # build but don't run
```

## Validate one model without Rust

If a detector's numbers look off, check the model + sidecar directly in Python — it
applies the *same* preprocessing the Rust core does, so a Python/Rust disagreement
isolates the bug to one preprocessing implementation:
```bash
. .venv/bin/activate
python scripts/verify_onnx.py models/adamcodd-vit-nsfw test/static/testImages/allowed.jpg
```

## Things to know

- **`ort` API**: ort 2.0 is a release candidate (not API-stable). The only version-
  sensitive code is `try_extract_tensor` in `src/detector.rs` (clearly commented). If
  a future `ort` bump fails to compile, that's the ~3 lines to adjust.
- **Adding a detector** needs no Rust changes: drop `models/<name>/model.onnx` +
  `preproc.json` and re-run. The registry auto-discovers it.
- **The shipped detector**: this project now ships a single model,
  `adamcodd-vit-nsfw` (AdamCodd ViT-base, Apache-2.0) — ship-safe for a
  closed/paid app. It's the only recipe in `convert_models.py` and the only
  entry in `CATALOGUE` (`detectors.rs`) and `models/thresholds.json`. The other
  candidates evaluated earlier (Marqo, Falconsai, SigLIP2, NSFWJS, OpenNSFW2,
  Bumble) were dropped; NudeNet (AGPL-3.0) was never shippable and `setup.sh`
  still deletes any stale copy.
