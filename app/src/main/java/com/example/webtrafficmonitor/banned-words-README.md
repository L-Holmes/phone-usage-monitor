# Sexual-content filter add-on — README & integration guide

Two **separate** mechanisms, both driven by editable files:

1. **A sexual-word TEXT filter** — scores a web page's text/title/URL using four small,
   hand-curated word lists, with context-aware handling of ambiguous words
   ("hot", "girls", "women"). These lists are mine to write and yours to edit; there
   is no repo to fetch them from, so they're simply bundled.
2. **An adult-WEBSITE blocklist** — a big merged list of porn domains from public
   repos (StevenBlack + Blocklist Project + UT1). It is regenerated **fresh at build
   time** and **bundled into the APK**. The app does **no networking** and needs **no
   INTERNET permission** — it just reads the list that was baked in when you built.

> **Why two things?** "explicit_sexual.txt" is a *word* list for analysing page
> *text*. "adult_hosts.txt.gz" is a *domain* list for matching *websites*. They look
> similar but do different jobs and never mix. Only the domain list comes from
> upstream repos, so only it gets refreshed at build time.

## 1. The blocklist is built at BUILD time, not on the phone

`tools/build_adult_blocklist.py` downloads the source lists, merges + de-duplicates
them, drops a `NEVER_BLOCK` safety set of mainstream apexes (so e.g. `tumblr.com`
itself is never blocked, but a porn subdomain of it still is), sorts the result, and
writes `adult_hosts.txt.gz`. Your `deploy.sh` now runs it before `./gradlew
assembleDebug`, so **every build bakes in a current list**.

Run it manually any time:
```bash
python3 tools/build_adult_blocklist.py --gz-only --out app/src/main/assets/blocklist
```
Latest build: **552,128 unique hosts**, ~2.95 MB gzipped. Flags: `--include-dating`
adds the UT1 dating category; `--ut1-adult-tgz <file>` folds in the full official UT1
adult list if you download it separately.

On the device, `DomainBlocklist` gunzips the bundled asset into private storage **once
per install** (keyed off the app's update time, so a freshly deployed build is always
re-extracted), then binary-searches it on disk — 550k+ hosts at ~0 heap. If you ever
forget to generate the asset, domain blocking is simply inactive (the text filter
still works) and nothing crashes.

> **Keep the gz out of git history** if you like — it's a build product. Add
> `app/src/main/assets/blocklist/adult_hosts.txt.gz` to `.gitignore`; `deploy.sh`
> recreates it. (Or commit it; either works.)

## 2. The word tiers and how to edit them

One word per line; `#` comments and blank lines ignored. There is **no phrase list** —
combinations are handled by the context rule (section 3).

| File | Meaning | Counts… | Weight |
|------|---------|---------|--------|
| `explicit_sexual.txt` | Hardcore/clinical, sexual in every context ("blowjob", "porn"). | on its own | **6** (`EXPLICIT_WEIGHT`) |
| `strong_sexual.txt` | Always-adult ~99% of hte time ("sex", etc.). | on its own | **4** (`STRONG_WEIGHT`) |
| `subtle.txt` | Suggestive but innocent too ("lingerie"). | on its own | **2** (`SUBTLE_WEIGHT`) |
| `dual_meaning.txt` | Ambiguous ("hot", "girls", "women", "wet"). | only with a sexual word nearby | **3** (`DUAL_SEXUAL_WEIGHT`) |

**Re-tier a word by moving its line between files** — no code change. `strong_sexual.txt`
is the tier you asked for: always-adult words count on their own, but a touch softer
than hardcore so a single stray use is tolerated.

> **Heads-up on "sex":** the one word in `strong_sexual.txt` with real innocent uses
> (sex education, "sex: male" on a form). A single mention won't block, but a page
> that repeats it (a sex-ed article) **will**. Move it to `dual_meaning.txt` if you'd
> rather it only count next to another sexual word.

## 3. The text-scoring algorithm (what you tune)

Knobs at the top of `BorderlineScorer`:

```kotlin
const val THRESHOLD = 10            // points to block  (main knob)
const val EXPLICIT_WEIGHT = 6
const val STRONG_WEIGHT = 4
const val SUBTLE_WEIGHT = 2
const val DUAL_SEXUAL_WEIGHT = 3
const val PER_WORD_CAP = 6          // one word counts at most this many times
const val CONTEXT_WINDOW = 5        // words each side that count as "near"
const val TITLE_URL_MULTIPLIER = 2  // title/URL hits worth this much more
```

`PER_WORD_CAP` is the *"bikini ×10 = bad, bikini ×2 = fine"* knob. Title/URL ×2 means a
single explicit word in the address/title is enough.

### The "is this 'hot' sexual?" context rule
A dual word scores **nothing alone**. It counts only when a sexual **indicator** (any
explicit/strong/subtle word) sits within `CONTEXT_WINDOW` words of it:
```
"hot chocolate recipe"   -> nothing sexual nearby -> ignored
"hot naked girls"        -> "naked" near "hot"/"girls" -> they count
"women in engineering"   -> nothing sexual nearby -> ignored
"horny women on cam"     -> "horny" near "women" -> "women" counts
```

### Verified examples (defaults, THRESHOLD 10)
| Page | Score | Blocked? |
|------|------:|:--------:|
| `bikini` ×10 | 12 | yes |
| `bikini` ×2 | 4 | no |
| "hot chocolate, hot and cozy" | 0 | no |
| "hot naked girls" | 10 | yes |
| "watch free porn here" (body, once) | 6 | no |
| title "Free Porn Videos" | 12 | yes |
| "porn … more porn" (repeats) | 18 | yes |
| "girls and women in tech" | 0 | no |
| "…the vagina… once" (clinical) | 6 | no |
| "enter your sex and date of birth" | 4 | no |
| "sex education… sex… sex ed" (repeats) | 16 | **yes** (the "sex" trade-off) |
| "follow me on onlyfans" (once) | 4 | no |
| URL `site.com/porn/videos` | 12 | yes |
| "horny women on webcam" | 11 | yes |
| "slut slut slut" | 12 | yes |

Too strict → raise `THRESHOLD` / lower weights / shrink `CONTEXT_WINDOW`. Missing porn
→ lower `THRESHOLD` / raise weights / add words. (Page text is sampled to
`MAX_TEXT_CHARS` = 1000 in your service; raise it to count repeats over more of a page.)

## 4. IDIOT-PROOF integration — exactly what to change

**No manifest change.** The app does no networking now, so you do **not** add the
INTERNET permission. (If you added it after my last message, remove it.)

### EDIT A — load the lists when the service connects
In `PageMonitorAccessibilityService.onServiceConnected()`:

**BEFORE**
```kotlin
    override fun onServiceConnected() {
        super.onServiceConnected()
        instance = this
        overlay = OverlayController(this)
        BlockRules.load(this)
        AppBlocklist.refresh(this)
        loadKeyboardPackages()
    }
```
**AFTER** (two new lines)
```kotlin
    override fun onServiceConnected() {
        super.onServiceConnected()
        instance = this
        overlay = OverlayController(this)
        BlockRules.load(this)
        AppBlocklist.refresh(this)
        loadKeyboardPackages()
        WordLists.load(this)            // NEW: load the sexual-word tiers
        DomainBlocklist.warmUp(this)    // NEW: extract (once per build) + open the bundled list
    }
```

### EDIT B — consult the new filters when deciding to block
In `evaluateBlock(...)`, find this single line (just after the `val rule = ...` block):

**BEFORE**
```kotlin
        val baseReason = appGuard ?: rule?.let { describeRule(it) }
```
**AFTER**
```kotlin
        val baseReason = when {
            appGuard != null -> appGuard
            // Known adult site (bundled blocklist) — web pages only.
            host != null && DomainBlocklist.isBlocked(host) -> "Adult site (blocklist): $host"
            // Your hand-typed BlockRules (unchanged).
            rule != null -> describeRule(rule)
            // Sexual-content text score — web pages only.
            host != null -> BorderlineScorer.evaluate(title, url, content)?.reason
            else -> null
        }
```
Everything after this already works off `baseReason` + `host`, so a content/site block
escalates and covers exactly like a keyword block. **Precedence:** app-screen guard →
adult-site blocklist → your `BlockRules` → sexual-text score.

### EDIT C — add the build step (already done in the provided deploy.sh)
If you keep your own `deploy.sh`, add this block **before** `./gradlew assembleDebug`:
```bash
ASSET_DIR="app/src/main/assets/blocklist"
echo "🧱 Refreshing bundled blocklist..."
python3 tools/build_adult_blocklist.py --gz-only --out "$ASSET_DIR" \
  || { [[ -f "$ASSET_DIR/adult_hosts.txt.gz" ]] && echo "⚠️ using existing asset" || { echo "❌ no blocklist"; exit 1; }; }
```
(Or wire it into Gradle with a `preBuild`-dependent task that runs the same command —
the provided `deploy.sh` already does it the simple way.)

### (Recommended) don't double-compress the asset
The asset is already gzipped, so tell AAPT to leave it alone (smaller APK, faster build):
```kotlin
// app/build.gradle(.kts) inside android { }
androidResources { noCompress += "gz" }   // AGP 8+
```
(This is optional — extraction works either way because `assets.open()` always returns
the original bytes.)
