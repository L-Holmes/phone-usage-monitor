# BYPASS SERVICES - blocked in every mode above Off.
#
# None of these hosts adult content. They RE-SERVE somebody else's page from their own
# domain, which is precisely what defeats a host-based block: the address bar says
# "translate.google.com" and the screen says whatever was blocked. Every published guide
# on getting round a content filter names these in the first three steps.
#
# Four families:
#   • TRANSLATION PROXIES - paste the URL, read the page through the translator.
#   • CACHES AND ARCHIVES - the page as it was, served from an archive's domain.
#   • READER / TEXT EXTRACTORS - strip a page to its text and re-host it.
#   • WEB PROXIES AND "UNBLOCKERS" - openly advertised as filter circumvention.
#
# URL SHORTENERS ARE HANDLED DIFFERENTLY - see the note at the bottom.
#
# A bare domain also covers its subdomains. One host per line, "#" = comment.
# LANGUAGE-NEUTRAL. Loaded by FilterData -> BlockedCategories.

# ── NOTE ON URL SHORTENERS ───────────────────────────────────────────────────────────
# bit.ly, tinyurl and friends hide the destination from a host check, and the community
# lists carry ~10,000 of them. They are NOT listed here on purpose: unlike everything
# above, a shortener has an enormous legitimate life (every newsletter, every QR code,
# every "share" button), so blocking them outright would break far more than it protects.
#
# The right handling is behavioural, not a list: treat a known shortener host as an
# UNKNOWN DESTINATION and re-check the moment the redirect lands. That belongs in the
# service, not in this file. Until it exists, the redirect target is checked normally by
# the address-bar read, which catches most of it a beat late.
