# FILTER-CIRCUMVENTION SERVICES - blocked in every mode above Off.
#
# Sites whose ONLY purpose is to fetch a blocked page and re-serve it from their own domain.
# They advertise themselves that way. That is the entire test for being on this list.
#
# ── WHAT WAS REMOVED, AND WHY IT IS NOT COMING BACK  (2026-08-04) ────────────────────
# This file was originally three times longer. It carried Google Translate, DeepL,
# translate.com, archive.org, the Wayback Machine, archive.today, 12ft.io, printfriendly
# and the rest - on the reasoning that all of them CAN be used to read a blocked page.
#
# They can. So can any text box. Every one of those is a legitimate tool with an ordinary
# daily use: translating a page, reading a source, checking what a site said last year.
# The Internet Archive is a library. Blocking a library because somebody could misuse it is
# exactly the over-blocking this app is supposed to be better than - and the reason it was
# wrong here in particular is that WEB BROWSING IS MONITORED LIGHTLY ON PURPOSE. The
# Firefox add-on reads the images on whatever page ends up on screen, proxy or not, and the
# word scorer reads the text. A proxied porn page is still a porn page to both of them.
#
# What survives is the set with no second use: the "unblock any site" proxies. If you find
# yourself adding a general-purpose tool to this file, that is the signal to stop.
#
# URL SHORTENERS are deliberately absent for the same reason - see the note at the bottom.
#
# A bare domain also covers its subdomains. One host per line, "#" = comment.
# LANGUAGE-NEUTRAL. Loaded by FilterData -> BlockedCategories.

# ── NOTE ON URL SHORTENERS ───────────────────────────────────────────────────────────
# bit.ly, tinyurl and friends hide the destination from a host check, and the community
# lists carry ~10,000 of them. They are NOT listed here on purpose: a shortener has an
# enormous legitimate life (every newsletter, every QR code, every share button), so
# blocking them outright would break far more than it protects.
#
# The right handling is behavioural, not a list: treat a known shortener as an UNKNOWN
# DESTINATION and re-check when the redirect lands. Until that exists, the redirect target
# is checked normally by the address-bar read, which catches it a beat late.
